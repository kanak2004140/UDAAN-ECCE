### NCERT content & AI tutor pipeline (paused earlier — now the active focus)

Target end state: the assistant retrieves real NCERT-sourced material for a topic/age-band via RAG, and teaches the child with it — as generated text/speech for kids who can read/listen, and as video+narration for toddlers who can't. Everything must degrade gracefully offline. See `[[project-vision-ncert-ai-tutor]]` memory for the full product vision and rationale behind each design choice below.

- [x] **Phase 14 — `ContentSource` model + migration.** The table that tracks every ingested resource: source URL, publisher, license, file hash, attribution, review status — before any real content touches it. *(Committed; migration applied.)*
- [x] **Phase 15 — NCERT scraper, proof of concept.** `backend/app/ingestion/ncert_scraper.py` walks `https://ncert.nic.in/textbook/pdf/<book_code><chapter>.pdf` (a real, verified stable URL pattern), downloads each chapter, hashes it, extracts text via `pypdf`, and records it as a `ContentSource` row (`pending_review`). Idempotent on `file_hash`. Verified live against `ncert.nic.in` (2 real chapters ingested).
- [x] **Phase 16 — pgvector + chunking + embeddings.** `backend/app/ingestion/chunk_and_embed.py` chunks extracted text (paragraph-aware, ~1000 chars, overlap) and embeds with local `sentence-transformers` (`all-MiniLM-L6-v2`, fully offline, no API cost) into a new `ContentChunk` table. **Caveat:** the `pgvector` Postgres extension isn't installed on this machine (needs a system-level install with admin rights, not automatable from here) — embeddings are stored as plain `ARRAY(Float)` for now, with cosine similarity computed in Python at retrieval time. Swap in `pgvector.sqlalchemy.Vector` + an ANN index once the extension is installed; no other code needs to change at this content volume.
- [x] **Phase 17 — Age-group & topic classification for that first resource.** `backend/app/ingestion/classify_content.py` gives rule-based topic *suggestions* (keyword overlap against existing `Topic` rows) that a human confirms via CLI flags; confirming cascades `age_group`/`topic_id`/`review_status` down to the source's chunks. Verified both paths: a confirmed approval (cascades to 65 chunks) and an explicit needs-review flag (content with no matching topic correctly surfaced as "needs manual review" rather than guessed).
- [x] **Phase 18 — RAG retrieval + text lesson generation.** `backend/app/services/lesson_generation.py` retrieves a topic's approved chunks by cosine similarity and calls the Anthropic API to generate an age-toned lesson script, grounded only in retrieved text. Exposed via `POST /lessons/generate` (new `lessons` router) plus a new read-only `GET /topics` router (needed for topic lookup and the frontend picker). Retrieval verified working end-to-end; generation verified to fail cleanly with a clear error when `ANTHROPIC_API_KEY` isn't set. **Action needed: add `ANTHROPIC_API_KEY` to the root `.env` to enable live generation.**
**Content scope (decided 2026-10-04):** NCERT Class 1-4 only, subject-wise, ingested **natively per language** so every fact traces to NCERT's own text (no machine-translated grounding). Rolled out in 3 waves:
- **Wave 1 — English, Hindi, Urdu** (full 18-book sets). Hindi is extractable with PyMuPDF (small glitches, needs spot review); **Urdu PDFs are scanned images and need an OCR step first.**
- **Wave 2 — Marathi, Bengali, Tamil, Telugu, Kannada, Malayalam, Gujarati, Punjabi, Odia, Assamese.**
- **Wave 3 — Sindhi, Konkani, Maithili, Bodo, Sanskrit, Santhali, Manipuri, Nepali, Dogri, Kashmiri.**
- **Wave 1 setup — DONE (2026-10-04):** multilingual offline embedding model (`intfloat/multilingual-e5-small`, 384-dim, centralized in `app/services/embeddings.py`, cross-lingual retrieval verified for English/Hindi); languages created on demand (`ingestion/languages.py`, all 23 mapped) with `ContentSource.language_id` set; live-code check + retry on connection resets; batch CLI `python -m app.ingestion.ingest_wave --wave 1 --languages English [--dry-run]`; scanned PDFs flagged `needs_ocr` and skipped by chunking. English dry-run: 15/18 books live (retired codes `ceen1`, `ceap1`, `cemh1` are dead).
- **English Class 1-4 ingested (2026-10-04):** 195 chapters from 15 books (Arts, English, Mathematics, Environmental Studies, The World Around Us, Physical Education and Well Being), stored per language and book as `content/ncert/English/<Book> (Class N)/` with a `manifest.json` in each (see README). The PDFs (~1 GB) are git-ignored; the extracted text and manifests are committed. Next for this content: chunk/embed, organize into curriculum > subject > topic (`organize_content`), spot-check, then approve. Nothing is approved yet, so children see no NCERT content.
- **Still required per wave:** per-script extraction check (Hindi: spot-review PyMuPDF output; Urdu: OCR approach needed before ingestion yields text).

- [ ] **Phase 19 — Visual asset generation for younger children.** For 2-4 / 2-6, teaching happens through video/image + spoken narration, not text. Generate one **language-independent** video/animation asset per topic+age-band (no baked-in speech or on-screen text) — this is the expensive asset, so it's produced once and reused across every language.
- [ ] **Phase 20 — Multilingual script layer.** Translate each generated lesson script (from Phase 18, or the narration script backing a Phase 19 video) into target languages and store as lightweight `ContentVariant` text rows. Deliberately *not* re-rendering video/audio per language — text translation is cheap, video/audio duplication is not.
- [ ] **Phase 21 — Offline TTS integration.** Add an on-device offline text-to-speech engine that narrates a Phase 20 translated script live, in sync with a cached Phase 19 visual asset — no internet required, no pre-rendered audio files to store per language.
- [ ] **Phase 22 — Online/offline orchestration.** Make the assistant connectivity-aware: online → live RAG retrieval + live generation (Phases 18-19 run fresh); offline → serve previously cached visual assets (Phase 19) + on-device TTS reading the cached translated script (Phases 20-21). This is the actual offline/online feature split, not just a fallback error state.
- [ ] **Phase 23 — Repeat Phases 15-22 for a second and third resource.** Confirms the whole pipeline (scrape → chunk/embed → classify → retrieve/generate → visual asset → multilingual script → offline TTS) actually generalizes before scaling further.

### Frontend track (paired with the NCERT content & AI tutor pipeline)

A frontend audit (2026-10-03) confirmed the current Next.js app is a thin CRUD client with **no** global/shared state, **no** offline support (no service worker/manifest/IndexedDB), **no** i18n or language picker, and **no** video/audio player — `DemoActivityContent.tsx` only matches hardcoded `content_key` string prefixes to inline emoji/JSX, and the "speech synthesis" from Phase 9 is just the browser Web Speech API speaking one static hardcoded English greeting per age world, not driven by any real script. Each item below is paired with the backend phase it depends on, and **Phase 14F must land before 15F-21F**, since they all lean on the shared state it introduces.

- [x] **Phase 14F — Frontend foundations.** `lib/context/AppStateContext.tsx` (React Context, wrapped around the app in `layout.tsx`) now holds selected child, selected language, `navigator.onLine` connectivity status (a cached-content registry is deferred to 20F, which actually needs it). New `lib/api/topics.ts` and `lib/api/languages.ts` clients; the backend gained matching read-only `GET /topics` and `GET /languages` routers to back them (Curriculum/Subject still have no routes — out of scope here, add if a future phase needs them directly).
- [x] **Phase 15F — Age-differentiated topic selection UX.** `TopicPicker.tsx`: ages 4-8 get a real clickable topic picker; 2-4 gets no picker, the component auto-selects the first available topic itself ("assistant picked today's topic: ..."). Added as a new "AI Tutor" section alongside (not replacing) the existing activity flow in all three `learn/*/page.tsx`, so the hardened demo flow stays intact.
- [x] **Phase 16F — Generated lesson rendering.** `lib/api/lessons.ts` + `LessonPanel.tsx` call `POST /lessons/generate` with loading/error states and render the real generated lesson text, with source-count attribution. This sits beside `DemoActivityContent.tsx` rather than replacing it yet — swapping the demo renderer itself is a larger change left for when more topics have approved content.
- [x] **Phase 17F — Video + script player.** `VideoScriptPlayer.tsx` is a real component (`<video>` + caption script) used for the 2-4 age band via `LessonPanel`'s new `variant="video"` mode. **Caveat:** no video-generation backend exists yet (that's Phase 19), so `videoUrl` is always `null` for now and the player shows a "video coming soon" placeholder while still rendering the real generated script text underneath — wire a real `videoUrl` through once Phase 19 exists, nothing else in this component needs to change.
- [x] **Phase 18F — Language picker UI.** `LanguagePicker.tsx` + the `AppStateContext` language state, placed in the new AI Tutor section. **Caveat:** since backend Phase 20 (multilingual script layer) doesn't exist yet, selecting a language doesn't yet change generated lesson content — it only persists the choice app-wide, ready for Phase 20 to consume.
- [ ] **Phase 19F — Real offline TTS integration** *(pairs with backend Phase 21)*. Replace the hardcoded static greeting-string `speak()` calls in `LittleExplorerWorld.tsx`/`CuriousLearnerWorld.tsx`/`YoungAdventurerWorld.tsx` with script-driven narration fed from fetched lesson/narration text, synced to the Phase 17F video player. Verify genuinely offline operation — browser Web Speech API voice availability isn't guaranteed offline in every browser, so this may require bundling an on-device TTS engine rather than relying solely on `speechSynthesis`.
- [ ] **Phase 20F — Connectivity-aware orchestration** *(pairs with backend Phase 22)*. Add `navigator.onLine`-based detection and a real caching layer (service worker + IndexedDB/Cache API) to store video assets and scripts client-side, then branch the UI between live API calls (online) and cached playback (offline) — none of this infrastructure exists yet.
- [ ] **Phase 21F — Generalize across resources** *(pairs with backend Phase 23)*. Confirm the topic picker, lesson renderer, video player, language picker, and offline cache all work for a second/third topic without anything hardcoded to the first proof-of-concept resource.
